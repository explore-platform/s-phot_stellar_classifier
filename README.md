# S-Phot Stellar Classifier

Training data and original code release: [![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.10377253.svg)](https://doi.org/10.5281/zenodo.10377253)

## Description

An XGBoost based approach to classification of highly sparse, sampling biased photometric stellar data with extreme class imbalance using data generated by PySSED. 

See also the paper:  *Cody SE, Scher S, McDonald I et al. Machine learning based stellar classification with highly sparse photometry data. Open Res Europe 2024, 4:29*  [(https://doi.org/10.12688/openreseurope.17023.2)](https://open-research-europe.ec.europa.eu/articles/4-29)

## Quick start: run inference (predict)

Use **Python 3.9** (recommended). Python 3.14+ is not compatible with the pinned training stack in `requirements-train.txt`.

### 1. Clone and set up the environment

(on linux/macos)

```bash
git clone <your-gitlab-repo-url>
cd s-phot_stellar_classifier
python3.9 -m venv .venv
source .venv/bin/activate
pip install -r requirements-train.txt
```

### 2. Option A — Predict using bundled model artifacts (recommended)

This repository includes a pre-trained **Full** model under `artifacts/`:

- `model.pkl` — fitted XGBoost classifier  
- `label_binarizer.pkl` — multi-label class encoder  
- `feature_columns.pkl` — feature column order (PySSED → model)  
- `meta.pkl` — package name, class list, training metadata  

Score a PySSED `.dat` file (same 9-line header as training). Labels are optional at predict time.

```bash
python infer.py predict --input data/mock_predict.dat --output data/mock_predict_scores.csv
```

For your own stars, replace the input path with PySSED output prepared as described in [Preparing input data (Option A)](#preparing-input-data-option-a). See `data/mock_predict.dat` for a worked example (three stars).

### Preparing input data (Option A)

Option A uses the bundled **Full** model. The model itself only consumes **96 numeric features** after preprocessing, but **`infer.py` does not accept a stripped-down 96-column file**. You must supply a **PySSED export** with the **same table layout** as the training data (9-line header + one row per star, tab-separated).

#### Recommended workflow

1. **Run PySSED** on your target list (tool and version described with the [Zenodo dataset](https://zenodo.org/records/10377253)) so each object gets the same derived fields and SED columns as the reference training tables.
2. **Match the column schema** to the reference file:
   - Easiest: start from `data/mock_predict.dat` or one row of `df_plus_ms.dat` (from Zenodo) and replace data rows with your stars while **keeping all header lines and column order unchanged**.
   - Do **not** delete Photometry / Model / Dereddened columns to “reduce” the file; the spectral transform needs them even though they are not all direct model inputs.
3. **One object ID per row** in the first column (same naming rules as PySSED, e.g. `CD-60__1960`).
4. **Labels are not required** for prediction. `infer.py predict` can use a dummy labels column internally if you only pass a `.dat` file.

#### What the pipeline uses (conceptually)

| Stage | PySSED columns involved |
|--------|-------------------------|
| Astrometry & bias | `Adopted` **Value**: RA, Dec, PMRA, PMDec, Distance (RA/Dec converted to galactic *l*, *b*) |
| Atmosphere / fit | `Fitted` **Value**: Teff, Lum |
| Chemistry / temperature | `Adopted` **Value**: E(B-V), logg, [Fe/H]; `Ancillary` **Value**: Tspec |
| Spectral transform | `Photometry` **Value** + **Error**, `Dereddened` **Value**, `Model` **Value** (per band; duplicate wavelengths merged in code) |
| **Model input (96 features)** | Subset of the above after transform — see `artifacts/feature_columns.pkl` |

#### Missing or sparse photometry

- Empty or missing cells in PySSED notation (`[]`, `--`, etc.) are converted to NaN and are **expected** for sparse SEDs.
- After preprocessing, any feature column missing for a star is filled with NaN when aligning to `feature_columns.pkl`. XGBoost can score sparse inputs, but **classification quality depends on having enough bands populated** (same as in the paper).

#### Checks before running predict

```bash
# Smoke test on the bundled mock file
python infer.py predict --input data/mock_predict.dat --output data/mock_predict_scores.csv
```

If your file fails to load, compare its **line 1–9 headers** and **column count** to `data/mock_predict.dat`. Mismatched headers are the most common cause of errors.

### 3. Option B — Retrain and then predict

Only needed if you want to **regenerate** the pickles (e.g. after code changes or to match the paper train/test protocol via `main.py`).

1. Download the ms-augmented training tables from Zenodo (see [Data](#data) below):
   - `df_plus_ms.dat`
   - `classes_plus_ms.dat`  
   Place them in `data/`.

2. Train the Full model and write `artifacts/`:

   ```bash
   python infer.py train --package Full
   ```

   Alternative (80% train split + test metrics, saves per-package under `artifacts/<Package>/`):

   ```bash
   python main.py
   ```

3. Run predict as in Option A.

Hyperparameters for training are read from `tuning_results_5foldcv_2000_iter_ms_augmented/` (included in this repo). Optuna re-tuning is **not** required for inference.

## Input format (summary)

PySSED `.dat`, 9-line header, same schema as training. Details: [Preparing input data (Option A)](#preparing-input-data-option-a).

## Data

Option A does **not** require downloading the **large training tables** from Zenodo (~480 MB+). You still need a **standard PySSED `.dat` export** for the stars you want to score (same 9-line header and column layout as training—see [Preparing input data (Option A)](#preparing-input-data-option-a); e.g. `data/mock_predict.dat`).

For retraining or reproducing paper experiments, download the dataset from Zenodo: **[record 10377253](https://zenodo.org/records/10377253)** — *Machine learning based stellar classification with highly sparse photometry data*.

| File | Use |
|------|-----|
| `df_plus_ms.dat`, `classes_plus_ms.dat` | ms-augmented sample — **training / `infer.py train`** |
| `10percent_full.dat`, `10percent_labels.txt` | 10% sample — optional (`scripts/create_imbalance_plots.py`, `tuning_results_5foldcv_2000iter_no_ms/`) |

After download, put files under `data/` (filenames as above).

## Notebook

`notebooks/stellar_classifier_workflow.ipynb` walks through training (optional) and prediction. Register the venv kernel once:

```bash
pip install jupyter ipykernel
python -m ipykernel install --user --name s-phot-classifier --display-name "Python 3 (s-phot-classifier)"
```

## File descriptions

| Path | Purpose |
|------|---------|
| `infer.py` | CLI: `train` (fit + save artifacts), `predict` (score new `.dat`) |
| `main.py` | Paper-style train/test loop; saves artifacts per feature package |
| `explore_commons.py` | Data I/O, preprocessing, spectral transform |
| `tuning/` | Optional Optuna search (`tuning_script.py`, `XGBoost_Weighted.py`); see `tuning/README.md` |
| `tuning_results_5foldcv_2000_iter_ms_augmented/` | Tuned hyperparameters for ms-augmented models (used by train/infer) |
| `tuning_results_5foldcv_2000iter_no_ms/` | Tuned hyperparameters for 10% sample |
| `artifacts/` | Pre-trained Full model for inference (Option A) |
| `data/mock_predict.dat` | Small PySSED example for smoke tests |
| `scripts/create_mock_predict_data.py` | Regenerate mock predict files from training table |
| `scripts/create_imbalance_plots.py` | Optional paper experiment: class missingness vs F1 (needs 10% Zenodo data) |
| `requirements-train.txt` | Minimal dependencies for train/infer |
| `requirements.txt` | Full legacy environment export; **not required for train/infer** |
